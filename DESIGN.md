# Pennel design system

This is the desktop design contract approved on 2 November 2026 for [Glaze implementation #92](https://github.com/pennel-app/pennel/issues/92). The two-task-space simplification was approved on 4 November 2026. Runtime, human and device acceptance are recorded separately from design approval.

## Visual language

Pennel is a calm writing app with the immediacy of a small native desktop utility. The approved Glaze direction uses neutral surfaces, inset rounded navigation, compact controls and a unified toolbar. Locally bundled Inter carries desktop controls, navigation, reading and compact titles in both appearances. The chrome font role follows the desktop interface font. Pennel's marks and wordmark remain unchanged; mobile retains its warm Figtree/Instrument Serif identity. The original Swift app at `91775c1` remains a historical behavior reference rather than the current desktop appearance contract.

One main window has two primary task spaces, Dictation and Meetings, with Settings below. History and the optional Write in Pennel pad are visibly grouped directly under Dictation, before Meetings. Dictation also contains recent results. Meetings contains the meeting library, meeting-scoped questions and New recording. Sidebar search follows the selected task and remains the only search field; Cmd/Ctrl+F reveals and focuses it. Keep active recording status and a return action visible across both tasks and Settings. Restore the last task when reopening. Preserve all drafts, source targets, meeting selection and reading positions through navigation; legacy History, Settings and model links still resolve. The dictation pill never activates or takes focus. Closing the main window remains distinct from quitting.

Settings has five categories: Dictation, Meetings, Appearance, Sync & account and Advanced. Task readiness and setup sit beside the relevant task; remove the duplicate Overview/Models summary. Dictionary, styles, inputs, models, providers and experimental connections remain reachable within the appropriate category and compatible deep links. Keep category navigation vertical, keyboard accessible and usable at minimum size. Back returns to the previous work without changing capture. One compatible local speech recommendation leads setup, with size and requirements; Other options exposes the existing Cloud, provider and detailed model routes. Shared settings explain affected tasks before Apply.

Use spacing to group related controls before adding a container. Keep reading content within one opaque rounded workspace, compact source lists, aligned setting rows and progressive detail. Fine panel edges define shared boundaries; avoid a separate card around every item. Navigation selection stays neutral, blue identifies primary actions and focus, and errors/destructive actions use a separate red role. Success green confirms completed steps with text. On macOS, navigation and frontend toolbar surfaces may reveal a successfully attached native material host. Motion conveys an actual state change and respects reduced motion.

## Shared tokens

`assets/brand/tokens.json` is the source of truth. `python3 scripts/generate-theme.py` emits:

- `apps/desktop/src/theme.generated.css` for the base brand roles, retained by the dictation pill.
- `apps/desktop/src/desktop-theme.generated.css` for the `desktop-theme` overrides used only by the main frontend, including onboarding and prompts.
- `apps/desktop/src/pill-metrics.generated.ts` for the shared pill geometry.

`assets/ui/icons/manifest.json` owns the compact shared 24 pt icon paths and 1.7 pt rounded strokes. The same generator emits the local SVGs used by the active desktop interface. Original Forma styles and the bundled Inter font live in `apps/desktop/src/desktop-ui/`; retain their licenses. Adapt those scoped styles to the existing accessible controls and lifecycle. The retired Mac shell's Swift theme/icon outputs are no longer generated. Mobile branding continues to use the base tokens, canonical assets and retained MobileKit helpers; desktop overrides must not alter those values.

Edit the token source, then regenerate. `--check` validates output reproducibility and text contrast; `--self-test` verifies palette and generator failure cases. The generator has no third-party runtime dependency.

Core color roles are Surface, Chrome, Sidebar, Foreground, Muted, Border, Subtle, Hover, Field, Selection, Button, Button text, Accent, Danger, Live and Focus ring. Live is the brand orange for a live or recording signal on desktop surfaces; the ink pill keeps Soft wave. Components use these roles rather than adding private hex values. Desktop and base palettes are validated separately, including secondary text on selected rows and text over native navigation backings.

Desktop geometry follows the approved Forma baseline: 6 px outer insets, 16 px navigation/workspace corners, 24 px dialog corners and capsule buttons, search and segmented controls. Ordinary controls are 32 px high, explicitly compact controls 28 px, toolbar controls 36 px, sidebar search 30 px and source-list rows at least 34 px. Inter UI text is about 13 px, captions start at 11 px, page titles are 26 px and the dictation instruction is 30 px. Use sentence case and restrained tracking. Base mobile geometry and typography remain separate.

Compatibility names remain semantic: Paper maps to Surface, Background to Subtle, Ink to Foreground and Line to Border. These values adapt to appearance. Fixed artwork colors and dictation-pil colors have separate roles.

## Appearance

System / Systeem follows the operating system. Light / Licht and Dark / Donker override it for every open product window, menu, dialog, picker and editor. Apply the preference before the window is shown and update it live without replacing focused inputs.

Both appearances have the same geometry, content and control states. Desktop light uses white content and a neutral gray sidebar; dark uses the token-defined near-black content and sidebar surfaces. Readable text contrast is at least 4.5:1, including metadata and placeholders. Color never carries recording, error or selection meaning without an accompanying label, icon or accessible state. Keep the existing System/Light/Dark preference and propagate it to native menus and every open window without creating another theme setting.

The dictation pill stays Ink with Paper text and a Soft wave audio/processing indicator in both appearances. Do not invert it by reusing ordinary window foreground and background roles. Speaker identity uses the shared four-color set with appearance-specific readable variants; labels also identify the speaker.

## Onboarding

Keep onboarding in its existing dedicated window. Do not draw an in-content title bar or imitate system window controls. A small Pennel label and stable actions provide orientation; keep the action reachable when content must scroll.

Welcome offers Try dictation or Record a meeting. Carry that task through speech setup, relevant access and the first real task. Recommend a supported local setup with a clear one-time download and processing explanation; model names, Apple dictation and user-chosen providers remain available under Other options. The footer owns the next action and truthful download/progress states. Keep interface language independent of speech language and user content.

Show real model metadata, progress and errors. Permission controls describe their task and provide the actual recovery action. Calendar and system audio are introduced when meetings need them. Denied or unknown access must not become an unexplained disabled dead end.

Dictation practice uses the actual configured speech engine and a visible editable result field. The configured shortcut and manual recording action share the same session. Practice never falls back to another app or the clipboard. A real nonempty result is required for successful dictation practice; setting up later preserves a resumable state. The meeting path opens the actual recording workflow rather than treating a simulated dictation as meeting success. Optional voice enrollment belongs in the meeting context and must not extend ordinary first use; older saved voice-step progress remains recoverable.

## Model setup

Task readiness shows the current service, readable model name, processing destination and readiness beside Change or Finish setup. Task settings and recovery use one chooser. Lead with the compatible local speech recommendation, then offer On this computer, Pennel Cloud and My own provider under Other options; retain unavailable choices with an explanation. Keep connection setup, permissions and explicit downloads in that flow, showing destinations and download sizes before acting. Search remote models by name or ID, with retry and manual ID entry available when the catalog is unavailable.

Model selection and sample testing leave the active task unchanged until Use this setup succeeds. Cancel or Escape returns to the originating work without applying the draft. Connection/key saves, downloads and sign-in are separate explicit actions and can remain after cancellation; say so in the chooser. Missing local assets never select a different model implicitly. Apply changes one task atomically and keeps other choices intact. Before editing a shared connection, name its affected tasks. A sample test uses only bundled synthetic content, reports the configuration actually tested and loses its success state when that configuration changes, including during Apply. Subscription clients and remote server endpoints belong under My own provider, with their processing destination explained explicitly.

Experimental connections start collapsed under Experimental connections — setup and testing only. Explain that ordinary dictation, meeting processing and search do not use them. Missing connections get an explanatory empty state and Add connection action rather than a blank dropdown. Keep required OpenRouter upstream routing visible; optional identity, input-budget and timeout fields belong in Advanced. Preserve saved settings and English/Dutch parity; this desktop chooser refinement does not redesign the iPhone model-setup flow.

## Workspace and data entry

Use persistent Dictation and Meetings controls in the main sidebar, with History and Write in Pennel nested directly below Dictation and before Meetings. Returning to Dictation restores its previous home or pad surface and saved text; History recovery links highlight the requested result in main. An owned pad dictation must finish or be explicitly cancelled before leaving while it is listening or processing. Navigation must explain that requirement and keep the active session intact rather than silently cancel it.

Dictation leads with a clear readiness state and the shortcut in another app. Finish setup is primary while recording is blocked; Try it here opens safe owned practice when ready, without changing saved first-use progress. Keep ordinary instructions short after setup and speech/text processing details available through a disclosure. Recent results offer direct Copy without leaving the task or processing the words again; History retains the detailed recovery routes. Refreshing recent results preserves known rows and keyboard focus, explains read failures and clears those errors after recovery. Dictation settings is secondary when the task is ready. The persistent editable pad remains separately available. Its optional external-paste setting applies only to pad sessions and shows the captured target app. Text remains in the pad if external delivery is unavailable or cancelled. Global dictation freezes its current external destination when recording stops and never retargets after asynchronous processing. Completion distinguishes inserted, copied, saved and retained-for-recovery results.

The floating pill shows at most two recent lines of real recognition text above a small listening/working indicator. It does not activate Pennel or capture input focus. Provisional text replaces earlier revisions rather than accumulating duplicates; working retains the current caption, and cancel, hide or a new session clears it. Batch providers show their final recognition text after recording rather than implying streaming. Shared pill metrics define the same bounded desktop geometry on all supported platforms.

The toolbar New recording action and Cmd/Ctrl+N start capture immediately after draft/session navigation barriers. If startup is blocked or fails, show the recoverable New meeting form with microphone repair, processing/system-audio explanation, setup/settings and retry. Return to an existing busy or retained recovery session instead of creating another. While recording, the same 36 px toolbar control grows into one fixed Ink capsule with Soft wave level bars, localized Recording and elapsed time, a return action and a distinct Stop button. Keep it visible across both tasks and Settings; clear levels as soon as capture stops and reject levels from earlier sessions. Live levels stay local, contain only a session identifier and normalized level, and publish at most 20 times per second. The Meetings sidebar puts the active row under Now, preserving that row and omitting it from date groups. A collapsed sidebar gives its visibility toggle a filled state. Preserve finishing and recovery routes.

Meeting notes remain in one retained workspace from capture through processing, review and reopening. Capture keeps its stationary title, recording state, elapsed time and Stop. A finished meeting has a compact title/metadata/people header with primary Share and More, followed by one scrolling document: Summary, then Your notes with Private · left out when you share. Finished review has no Notes/Summary tabs; source navigation scrolls to the appropriate document section and retains selection and return position. The same note editor survives finalization. Transcript processing is labelled only from known frozen capture provenance; summary provenance waits for recorded structured provenance. Transcript, Review (finished meetings) and Ask share one segmented companion control with a close action. Review shows the count of open suggestions and simple Accept/Edit/Dismiss cards; accepted cards stay quiet with Undo. Evidence, frozen processing records, related/prior statements and explicit insertion/recovery remain under Details, with source errors and insertion ambiguity visible. Copy accepted items stays pinned, and the completed review explains what is ready to copy. Language, qualification, Find and cancellation retain their existing gates and remain reachable in Analysis details, open in an empty state. At window widths of 1100 px or more, Transcript opens by default during capture and Review opens by default for finished meetings; below that width the companion starts closed and opens as an overlay over the retained document. Preserve explicit open/close and tab choices through resizing. Closing or inspecting a source retains the writer, selection and return scope. Provisional capture text appears inside the transcript with the Live role and label. Your notes and Summary remain distinct. Summary opens in a formatted reading view; Edit enters Markdown editing and Done returns to reading. Routine privacy and processing detail starts collapsed, with a visible setup action when needed; stale-source warnings, save failures and recovery stay outside that disclosure. Generating or saving a summary cannot replace an active note editor, steal focus or lose selection. Keep secondary formatting, people, speaker setup, templates, suggestions and file actions in contextual controls and More, with unavailable controls and explanations still discoverable. Opening a secondary tool shows its selected task and a clear return to the same document, writing selection and reading position. Asynchronous results and errors remain owned by their originating tool.

Automatic summaries use a shared explicit Unanswered / Manual / Automatic policy. New and upgraded profiles persist Unanswered until the owner makes a nonblocking choice; manual generation remains available, and automatic work requires Automatic. Explain that personal summaries can use typed notes and finalized transcript, and show their actual processing destination. Summary editing acknowledges Saving / Saved / Not saved, offers retry and recoverable revisions, and stages generated replacements for review when edits exist. Use stable meeting/source identity and revision checks to reject stale completion or duplicate automatic work.

Suggestion analysis has its own Unanswered / Manual / Automatic consent and optional explicit language fallback. Summary consent never enables it. After Stop, automatic suggestions run only after the summary returns, through the exact qualified finished-meeting analysis path and only when foreground impact is accepted. Requests contain finalized transcript utterances and their neighbours as untrusted data, with no typed notes, title or speaker names. Consume one durable metadata-only attempt per transcript digest before credential access and never retry automatically. Keep manual Find suggestions available, preserve review cards when source or receipt files are damaged, and explain changed transcripts or unavailable setup. The shared settings do not enable live suggestions or automatic iPhone analysis.

Copy/export opens a dialog with a formatted, safely rendered preview of exactly the selected output, with an explicit Markdown view. Changing the view does not prepare new content or change the immutable payload used by Copy or Save. Keep review content scrollable and action controls reachable at minimum size and with enlarged text. The default shareable scope uses finalized transcript sources with known current provenance and excludes private notes and content derived from them. It never reuses unknown legacy provenance or falls back to personal notes. Personal copy/export remains a separately labelled owner choice and always includes Your notes after the summary when both exist. Nearby source inspection and return preserve the originating answer or document context.

Questions keeps This meeting or Meeting library beside the composer, including after answers exist. An empty conversation with no draft offers three optional starters; selecting one prepares an editable, durable draft and never sends it. Starter text follows the configured content/speech language, with English fallback, independently of interface labels. Relabelling the interface never translates a prepared question, replaces a draft or interrupts composition. Existing provider setup, cancellation, source citations and returns remain available.

An unanswered summary policy shows a card naming the actual processing destination and finalized-transcript plus private-note inputs. Create saves Automatic only when its unchecked-by-default checkbox is chosen; otherwise it saves Manual before inference. Not now writes durable per-meeting metadata without changing global consent, and reopening shows a quiet one-off Create action. Rendering and reading dismissal metadata never fetch credentials or start a provider. Only an empty, unedited saved summary can be created directly; existing or edited content uses the guarded candidate path. Metadata-only progress drives static placeholders and a reduced-motion-aware reveal without replacing active writing. Settings retains the separate policy control.

An unavailable summary or regeneration action always has a visible explanation and useful setup action, including when an older summary exists. Task setup uses the existing model/provider capabilities and credential store, preserves the originating document and returns to it after completion or cancellation. Never switch a provider or send a transcript merely to make a setup screen appear successful.

Keep draft text, selection, scroll position and focused controls stable during model progress, theme updates, permission refresh and navigation. Preserve recording status when users visit another section. A generic success message must not occupy every otherwise empty surface; show acknowledgement after a relevant action.

## Components and acceptance

Every control has clear default, hover, keyboard focus, selected, disabled, loading and error states. A disabled primary button keeps its label readable and does not inherit a secondary hover background. Empty states explain what belongs there and provide a useful first action. Unavailable platform features keep the same control and a short explanation in the selected interface language. Keyboard focus, logical headings and important status announcements remain usable at minimum sizes and with enlarged text. Reduce Motion removes movement and decorative animation while keeping short opacity and colour fades.

Standard popup choices and action/context menus use the operating system's native menu through Tauri. Their trigger geometry, labels, ordering, actions and disabled semantics are shared; native menu rendering follows each platform. Product content uses the existing opaque surface tokens. Source-list refreshes preserve stable rows, focus, selection and scroll, and pending navigation acknowledges the destination while waiting for durable draft saves.

## macOS materials and chrome

The existing macOS service library hosts the Tauri webview inside a public `NSGlassEffectView.contentView` on macOS 26 and newer. Glass is exposed through the navigation, titlebar region, toolbar and recording prompt. The toolbar controls and product views remain in TypeScript. A single host provides one material geometry; individual HTML controls do not gain separate native glass shapes or merging effects.

Use regular glass and let AppKit render it. On macOS 14.4–15, use the system sidebar/popover visual effect material. Reduce Transparency and Increase Contrast select opaque navigation/control backings; Increase Contrast also strengthens focus and control boundaries. Reduce Motion removes movement and decorative animation while keeping short opacity and colour fades. Native environment changes update styles in place, retaining draft text, focus and selection. Native attachment failure leaves an opaque, usable interface.

Let AppKit position the real traffic lights and preserve the accessible window title. An empty unified native toolbar supplies the standard window geometry; every action control remains in the shared frontend. Reserve the measured native control extent and keep interactive controls outside the drag region. Use the shared 52 px toolbar band and 36 px toolbar controls. The inset sidebar begins 6 px from the window edge and includes the 46 px inner chrome band. Its visibility control is quiet and sits at the trailing edge, while the context title aligns with the 28 px reading inset. New recording/Return to recording stays vertically centered and shares the content footer actions' 22 px inset from the inner workspace edge. The toolbar has no second search control: the single sidebar search stays reachable through Cmd/Ctrl+F, which restores the sidebar and preserves the query. Sidebar presentation defaults to 220 px with 200–320 px bounds; preserve saved widths, visibility and current work. The workspace minimum remains 760×520. The fixed Ink dictation pill retains its nonactivating, click-through behavior.

Inspect the shared app against the approved Glaze composition and retained captures, using deterministic fixtures in English/Dutch and light/dark. Use app windows or offscreen rendering, not the user's screen. Cover native windows, first-use paths, dialogs, meaningful error/loading states, collapsed/resized navigation, minimum sizes and enlarged text. Browser fixtures establish layout and interaction evidence; actual native glass, traffic-light clearance, menus and close/reopen behavior need an isolated native app run. The legacy SwiftUI shells are retired under [cleanup #75](https://github.com/pennel-app/pennel/issues/75); Git history retains their source. Hardware capture, focus, clipboard, shortcuts, VoiceOver and human comprehension require separate evidence. The [usability and adoption protocol](docs/ux-adoption.md) defines the formative rounds and voluntary cohort; design approval is not a completed study. The [#141 implementation receipt](docs/evidence/simpler-pennel-141.md) records the simpler workspace checks and independent before/after review. The visual disposition covers only the two scored desktop views; native windows, other platform surfaces and human task completion retain their own acceptance gates.
