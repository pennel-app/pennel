# Fase 4 — iPhone (kern voor iOS, app, toetsenbord, meetings, sync, snel starten) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Pennel iPhone app on the same `pennel-core`: a dictation keyboard that hands recording off to the app's short background session, dictation and meeting recording started from the Action Button, Back Tap, Shortcuts and Control Center, physical meetings recorded through the microphone, and Pennel Cloud sync with the desktop through the unchanged Cloud v1 core modules and protocol.

**Architecture:** The core is cross-compiled for `aarch64-apple-ios` and `aarch64-apple-ios-sim` into an XCFramework, without the `local-models` feature, with an unchanged uniffi surface. Only the main app links the core; its data lives in the app's own container. The keyboard extension links only `PennelMobileKit` (pure Swift) and talks to the app through small JSON files in the App Group plus content-free Darwin notifications. The app keeps a background `AVAudioSession` open while a dictation session is "ready", discards samples until the keyboard sends `start`, then calls `PennelEngine::dictate`. Meetings use `MeetingSession` exactly as the desktop does. Sync runs `cloud_sync_run` from the app on foreground, after writes, on a 3-minute foreground timer and in `BGAppRefreshTask`.

**Tech Stack:** Rust (core as-is), uniffi 0.32, cargo targets `aarch64-apple-ios` / `aarch64-apple-ios-sim`, Xcode 27 / iOS SDK 27 with deployment target iOS 26.0, SwiftUI, AVFoundation, Speech (`SpeechAnalyzer`/`DictationTranscriber`), FoundationModels, AppIntents, ActivityKit, WidgetKit (`ControlWidget`), BackgroundTasks, AuthenticationServices. No third-party Swift packages.

**Repo:** `<app-checkout>`, a new branch `feat/iphone` from `main`. Task 10 needs `feat/pennel-cloud-v1` (plans 2 and 3) merged first; Tasks 1–9 and 11 do not.

**Spec:** `docs/superpowers/specs/2026-10-25-iphone-design.md`. Cloud API: `docs/superpowers/plans/2026-10-25-pennel-cloud-v1-2-core.md` (Interfaces blocks) and the Account-tab copy in `docs/superpowers/plans/2026-10-25-pennel-cloud-v1-3-app.md` Task 2.

## Global Constraints

- The keyboard extension never links `PennelCore`, never opens a network connection, never logs and never writes typed text anywhere. It writes only `command.json` and reads `session.json` / `result.json`.
- The app never retains or sends audio captured while the dictation session is only `ready`. Samples count only between a `start` and the matching `stop`/`cancel` command.
- `PennelEngine` data dir: `<app container>/Library/Application Support/Pennel`; meetings dir: `<app container>/Documents/Meetings`. Nothing the core locks or opens with SQLite lives in the App Group container (`0xdead10cc`).
- App Group files are written atomically (write `*.tmp`, then rename) and never locked.
- The uniffi surface is identical with and without the `local-models` feature; `scripts/build-core-ios.sh` fails if the generated `pennel_core.swift` differs from the Mac one.
- Never log dictated text, meeting content, file or folder names, e-mail addresses, tokens or keys. Logs hold durations, byte lengths, counts, states and error codes.
- Secrets in the Keychain with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, service `app.pennel.ios`. API keys and Cloud secrets stay in the app; the keyboard has no Keychain access group.
- Colours, fonts and sizes come from `assets/brand/brand.md` (Muted text is `#7A7268`, not the retired `#9B948A`). Fonts are bundled from `assets/brand/fonts/`.
- Dutch user-facing strings exactly as written in the spec and in this plan; labels shared with the desktop are copied from `apps/desktop/src/views/*.ts`, not retyped.
- Platform features iOS cannot support are shown disabled with the reason from spec §4.4, never hidden; each gap is recorded in `docs/desktop.md` (platform table) and `docs/ios.md`.
- Checks before any task is done: `cd core && cargo fmt -- --check && cargo clippy --lib --tests -- -D warnings && cargo test`, `cargo test --no-default-features` in `core/`, `make core && make test && make app`, `cd apps/desktop/src-tauri && cargo test`, and from Task 2 on `make ios-test`.

## Review Focus

1. **One dictation, one insertion:** the keyboard inserts a result exactly once and only for the command id it sent; a keyboard dismissed and re-shown, or a second keyboard instance, never inserts twice or inserts someone else's result. Test in Task 3 (`HandoffClient`) and Task 8.
2. **The microphone really closes:** after the session timeout, **Stop sessie**, an interruption or app termination, the `AVAudioSession` is deactivated and the keyboard shows "Sessie uit" within 5 s (stale heartbeat). Test in Task 3 (`SessionClock`, heartbeat) and Task 7.
3. **Ready means nothing kept:** samples captured while `ready` never reach the dictation buffer; only samples after `start` do. Test in Task 3 (`DictationBuffer`) and Task 7.
4. **Interrupted meeting:** a phone call during a physical meeting leaves a timestamp gap (via `push_audio_at`), recording resumes or stops cleanly, and finalising does not claim a complete recording. Test in Task 9.
5. **Same core, same API:** the iOS XCFramework has the same uniffi checksum as the Mac build; local-model calls without the feature return the Dutch error, not a panic. Test in Tasks 1–2.
6. **Sync stays Cloud v1:** a meeting recorded on the iPhone reaches the desktop with `pennel_id`, the recording meeting is never pushed mid-recording, and the iPhone sends platform `ios`. Test in Task 10.
