# Domain docs

This repository uses one shared domain context.

## Before exploring

Read root `GLOSSARY.md`, if present, and relevant ADRs in `docs/adr/`.

If these files do not exist, proceed silently. Do not suggest or create
empty scaffolding. The domain-modeling skill creates entries and ADRs
when terms or decisions are resolved.

## Layout

- `GLOSSARY.md`: repository-wide domain vocabulary.
- `docs/adr/`: numbered architecture decision records.

## Vocabulary and decisions

Use glossary terms consistently in issues, proposals, hypotheses and tests.
Reconsider invented synonyms; note real vocabulary gaps for domain modeling.

Explicitly identify conflicts with existing ADRs and explain the proposed
reason for revisiting the decision.
